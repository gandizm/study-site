同一份数据为什么既要交换、分层，又要排队？

先找对象，再比较三种交换

网络是由相互连接、能按协议交换数据的结点与链路构成的系统；主机承载应用，交换或路由设备帮助转送，通信介质与协议使交换成为可能。电路交换先建立并占用通信资源；报文交换在中间结点收齐整份报文再转发；分组交换将报文切成较小单元，便于共享与流水传送。

因特网以分组交换为基础。说“分组更快”时要说明突发业务、链路数、分组长度和首部开销；电路建立后持续发送可摊薄建立代价，不能把一种方式判成在所有题目里都最快。回看总论 P10–17、P26–38。

分层不是五个彼此直连的信箱

本课五层依次为应用、运输、网络、数据链路、物理层。同层对等实体按协议解释各自 PDU；本机上下层通过接口使用服务。逻辑上同层通信，真正发送时却必须依次使用下层，接收时再逐层处理。

服务说“下层给上层什么能力”，协议说“对等实体遵守什么规则”。PDU 是某层按该层协议处理的数据单元，同一段内容作为下一层的载荷后又会被封装。回看总论 P44–61、P74–90。

从一串比特到可收到的波形，要作哪些不同的选择？

谁产生信息，谁接收，线路上又是什么

信源产生消息，信宿是预定接收消息的对象；编码或调制设备把数据变成信号，信道承载它。物理层对上层提供比特流传送，不能因为线上是电压或光脉冲，就把它的数据单元改叫帧。

单工只允许一个方向；半双工可以双向但不能同时；全双工可同时双向。这是通信方向安排，不等于基带、带通或有线、无线的分类。回看物理层 P4–8。

编码题先写约定，不要凭波形外观猜零和一

波形选好了，还要让接口和介质配合

机械特性回答插头和针脚如何连接；电气特性回答电平、阻抗等信号要求；功能特性说明每条线干什么；规程特性规定信号出现的时序和步骤。回看物理主版 P3，接口专题真实来源 2.1 P27–34。

双绞线以绞合抑制干扰，同轴借内外导体和屏蔽传输，光纤用光传送且不受电磁干扰，但仍有衰减、色散、接续成本和距离约束。比较必须附上具体标准和部署条件，不能说某种介质“永不失真”。回看物理层 P18–29。

接入方式比较，沿最后一段介质读

ADSL 利用用户铜线的可用频带，通常上下行不对称，速率受距离与线路质量影响；HFC 先光纤后同轴，覆盖分支共享资源；FTTx 说明光纤到哪一级，其中 PON 的无源分光器只分合光，时隙授权由 OLT 等系统设备控制。回看物理层 P36–47。

容易混淆的地方

光纤到楼不等于光纤到户；共享接入也不等于每人永远获得标称总速率。

一段链路能发比特，为什么还不能保证一帧可靠交付？

帧先要能被完整认出来

链路是相邻结点之间的传输通道；数据链路还包含按协议控制传输所需的功能。点对点信道面对一个对端，广播信道则还要解决多站共享。链路层处理帧：封装成帧标出边界，透明传输使数据里的特殊图样不被误认作边界，差错检测判断收到的比特是否可能损坏。回看链路层 P4–17。

CRC 检查的是余数，不是“自动修好了数据”

条件：收发使用相同位序和生成多项式；实际标准还可能规定初值、反射与末尾异或，计算题按给定模型。

检测失败以后，靠哪条规则重新交付

停止等待是发一帧后等确认，超时才重发，序号用来识别重复帧。连续 ARQ 用滑动窗口让多帧在途：GBN 对丢失后的未确认帧采用回退重传，典型接收窗口只接受顺序下一帧；SR（原页写 SRP-ARQ）缓存允许范围内的失序帧，只重发需要补的帧。

原页把几种机制接在“停止等待”后面，不能据此把连续 ARQ 也归成停止等待。做窗口题先写序号空间、发送窗口、接收窗口与 ACK 含义，再走丢帧或丢确认的时间线。回看链路层 P29–48。

利用率从一次完整循环算，而不是只看传播

在无差错停止等待模型中，设数据帧发送时间为 、单程传播时延为 、ACK 发送时间为 ，忽略处理时间。分子是发送数据帧占用的时间，分母必须等到该 ACK 返回，发送者才能发下一帧。

这是发送端用于发送数据帧的时间比例；若求有效载荷效率，还要扣帧首尾。

条件：无差错、每帧单独确认、对称传播；有误码、超时或额外处理时须重建周期。

PPP 将这些任务做了哪些，没做哪些

PPP 帧读成标志、地址、控制、协议、信息、FCS、标志，协议字段指出载荷类型；异步字节式链路用转义处理特殊字节，同步比特式链路使用零比特填充。具体变换规则回看链路层 P23–28。

PPP 有成帧、透明传输和 FCS 检错，但基础 PPP 不因有 FCS 就提供逐帧确认重传式的可靠交付。不要把上一节 ARQ 的能力自动嫁接给 PPP。

地址题先找分界：部门越多，借位是下界还是上界？

网络层的包，带着什么服务承诺

本课把网络层数据单元称为分组、包或数据报。虚电路服务先建立逻辑连接并保留相应转发状态；数据报服务逐包按目的地址选择下一跳。因特网 IP 采用尽力而为的数据报服务，不自行保证不丢失、不乱序。回看网络层 P3–7。

IP 负责无连接的数据报交付；ARP 在本 IPv4 链路寻找下一跳 IP 对应的链路地址；ICMP 传送控制和差错报告；IGMP 管理 IPv4 多播组成员关系。ARP 不是替你直接查找任意远程主机的 MAC。回看 P9、P43–57、P87–94、P209–213。

先看前缀，再解释地址是哪一部分

IPv4 地址长 ，点分十进制把它分成四个八位组。历史 A、B、C 类的前导位依次为 0、10、110，对应默认前缀 /8、/16、/24；实际网络已给掩码或 CIDR 前缀时，必须优先使用它，不能仍按地址首字节硬套类别。特殊地址还要单独排除。

在通常不做地址转换的逐跳转发中，IP 目的地址标识最终目标接口，当前帧的目的 MAC 则标识这一跳的接收者；路由器转发时重新封装帧，TTL 等 IP 字段仍会变化。IP 首部还要读懂版本、长度、标识与分片信息、TTL、协议号、校验和及地址，而不是只会背地址长度。回看网络层 P14–21、P43–74。

同一地址与两个掩码，可以取出不同层次的前缀

用 IP 地址与子网掩码逐位 AND 得子网网络地址；与主机位掩码逐位 AND 得主机部分。若题目要求再区分原网络号与借来的子网号，还必须给出原前缀长度，不能仅凭最终掩码猜它。回看网络层 P22–31、P75–85。

部门需求逼你至少借多少，主机需求限制你最多借多少

设原 IPv4 前缀长为 ，等长划分时借 位作子网号，剩余主机位 。需要至少 个子网，就要有至少这么多不同子网号；每子网需要 个常规可用主机地址，就得留下足够主机位。

第一条给借位的下界，第二条给借位的上界，两条同时成立才可规划。

条件：等长子网划分、常规 IPv4 广播子网，；现代子网号通常不扣全零、全一两个子网。/31 点对点与 /32 主机路由另处理。

原清单的“最大”怎样校正，而不是照背

原页写“根据部门数确定最大的子网号位数”，仅凭部门数实际只能要求足够多子网，不能独自确定最大借位数。还需每个子网的主机需求、原地址块和是否等长划分；本伴读按这些约束解释，不把“最大”静默当成“最小”。

管理边界与算法边界不是一回事

自治系统 AS 表示由统一管理和路由策略控制的网络集合。IGP 在 AS 内部工作，RIP 和 OSPF 是本课典型；BGP 用于 AS 间的策略化路径交换。原清单里的 EGP 是“外部网关协议”类别名称，此处不是要求把 BGP 说成旧的同名 EGP 协议。回看网络层 P130–134、P178–194。

拿到地图，就反复扩展已确认的最短路

Dijkstra 给定非负链路代价，从源点出发，每轮选择暂定距离最小的未确定结点，再检查经它绕到邻居是否更便宜。要同时记录距离与前驱，最终由路径首跳形成转发表。它不是每一步只挑一条全图最短边，也不等于“只能用于静态路由”。回看网络层 P135–146。

只听邻居报价，就比较“先到邻居再继续”的总价

距离向量在结点 上比较各邻居 ：本结点到邻居的链路代价为 ，邻居到目的 的报价为 。算法与消息传播有时间差，坏消息可能慢收敛，不能把一次局部更新当成全网已稳定。回看网络层 P147–167。

是 的邻居集合；选择达到最小值的邻居作为候选下一跳。

条件：各代价使用相同度量；实际协议还规定不可达、超时、防环及选路规则。

用三个问题比较，不用两串缩写硬背

向谁发：RIP 与相邻路由器交换距离向量；OSPF 与邻居建立邻接，再在其相应区域内泛洪链路状态信息。发什么：RIP 关注目的网络和距离，OSPF 传播本地链路状态，使路由器得到本区域拓扑并运行最短路计算。何时发：RIP 有周期与触发更新；OSPF 对变化触发泛洪，也有周期刷新等维护。

RIP 通常以跳数为度量，OSPF 依据链路代价；BGP 还交换 AS 路径等属性并执行策略，不承诺从所有 AS 中选物理距离最短或时延最小的路径。回看网络层 P151–177、P179–194。

要发给一组人、跨机构内部网，或共用公网地址，分别找谁？

多播不等于向所有人广播

IPv4 多播把数据交给加入相应组的接收者；网络可在分叉处复制，不要求源逐个单播给每个成员。历史 D 类地址的前导位为 1110，地址块为 224.0.0.0/4；这不是普通单播地址的“网络号加主机号”结构。回看网络层 P203–213。

在以太网上，映射使用固定前缀 01-00-5E，并复制 IP 多播地址的低 位。原 IP 组标识有 位，因此会丢掉 位，同一个 MAC 可对应 个 IPv4 多播组；上层仍要检查实际组地址，不能只凭网卡接收就认定是自己订阅的组。

算映射时，只保留真正装得下的位

VPN 想连通受控网络，不是想节约每个公网地址

私有地址允许不同机构重复使用，因此不能在公共互联网中唯一定位某个内部主机，但机构内部路由器可以正常转发它们。全球地址按分配和路由体系使用；“全球”也不保证所有服务一定对外开放。

VPN 利用公共或共享基础设施形成逻辑专网。站点到站点方案连接两个网络的网关，远程接入方案连接个人终端与机构入口；隧道把内部包再封装，使公共网络能按外层地址转送。保密、完整性和身份认证要由所采用的安全机制保证，单有隧道不自动等于加密。回看网络层 P224–226。

内联网是机构内部的网络；外联网把特定资源向经授权的合作方开放，不是把整个内部网无条件开放给公众。要回答 VPN “为何用、如何用”，就同时说清可访问对象、内外层地址和安全机制。

NAT 改的是映射关系，NAPT 还借端口区分通信

静态 NAT 保持固定的一对一地址映射；基本动态 NAT 从地址池中临时分配一对一映射，并不自动让无限多主机同时共享一个外部地址；NAPT 将地址与端口等状态结合，才可让多条内部通信复用外部地址。

画题时把出去和回来两条路径都标明：外出包怎样转换，返回包靠哪个映射还原。NAT 可以缓解 IPv4 地址紧张，却不等于 VPN、加密或完整防火墙，也不是所有网络都必需。回看网络层 P228–232。

容易混淆的地方

多播组地址不是某台主机的单播地址。

内联网、外联网是组织与权限范围，不能仅凭画了一个隧道来判断。

IPv6 不只是地址变长：包怎样读，旧网怎样穿过？

先读固定部分，再沿下一个首部找到真正载荷

IPv4 首部可变长，含首部长度、首部校验和及常规分片字段；IPv6 基本首部固定为 字节，包含版本、通信量类、流标号、有效载荷长度、下一个首部、跳数限制和源、目的地址。扩展功能由相应扩展首部承载；下一个首部指向紧邻的一层，不能跳过中间扩展首部直接解释成 TCP。

IPv6 基本首部不再有 IPv4 式首部校验和，路由器不替原包分片；必要的分片由源端按规则处理。长度题需区分基本首部、扩展首部和上层数据，不能直接沿用 IPv4 总长度的分母。回看网络层 P95–115。

单播指向一个接口；多播指向一组接口；任播也分配给多个接口，但按路由选择交给其中一个，所谓最近是所用路由度量意义上的最近。IPv6 没有广播地址，不能照搬 IPv4 的广播主机位规则。回看网络层 P116–124。

长地址先展开，再省略，才能保证位置没移

IPv6 地址长 ，通常分成八组十六进制数，每组 。组内可省前导零；一串连续零组可用 :: 压缩，但一个地址中只能用一次，否则不能唯一知道省略了多少组。

伴读自拟：2001:0db8:0000:0000:0000:0000:0000:0001 可写为 2001:db8::1。十六进制组末尾的零不能随意删除，压缩也不能改变有效数字所在位置。

全球前缀、子网标识和接口标识，各供谁管理

常见全球单播规划把网络前缀分成全球路由前缀与站点内子网标识，后面是接口标识。常规 SLAAC 子网通常按 /64 边界使用；不能从这张层级图推出每一种 IPv6 地址都必定是同一前缀结构、所有链路都只能用同一个长度。回看网络层 P125。

伴读自拟：一个 /48 站点块分成 /64 子网，可用子网编号长度为 位，子网数量为 。这里数子网前缀，不套 IPv4 常规主机地址的减二。

双栈是会两套协议，隧道是把一套包裹在另一套里

双栈结点能运行 IPv4 和 IPv6，按通信对象及网络条件选用相应协议；这本身不是把任意 IPv6 包改写成 IPv4。IPv6-over-IPv4 隧道在入口保留内层 IPv6 包、加外层 IPv4 首部，穿过中间 IPv4 网络，出口再去掉外层。回看网络层 P126–129。

做过渡题沿入口、中间路由器、出口依次回答：谁看外层地址，谁处理内层地址，在哪一处封装或拆封装。不要只根据图中颜色变了就说完成了协议翻译。

容易混淆的地方

IPv6 任播不是复制给全部组员。

IPv6 地址类型、前缀规划和可达性是三个不同问题。

一帧穿过 AP 时，谁是眼前接收者，谁才是最终目的？

先画一张最小基础设施网

无线站 STA 经接入点 AP 接入基础设施 BSS。AP 在此承担接入点或基站作用，但不要因此把所有蜂窝基站概念都套到 Wi-Fi。SSID 是服务集名称，不是唯一 AP 地址，也不是信道号；基础设施 BSS 的 BSSID 通常标识相应 AP 的无线接口。

DS 是连接多个 BSS 的分配系统功能，可由适当的有线或无线网络实现；经 DS 组织的多个 BSS 可构成 ESS，正确名称是扩展服务集，原清单写“扩展的基本服务集”不够准确。仅把两个无关 AP 改成同一 SSID，并不自动完成同一 ESS 的连通与漫游配置。Wi-Fi 是相关互通认证与产品生态称谓，802.11 是 WLAN 的 MAC/PHY 标准系列。回看无线基础 P2–10。

听不见，为什么不表示不会撞到别人

普通无线站的自发信号远强于收到的远端信号，很难在发送中像共享有线以太网那样可靠检测碰撞；而且本地听到的环境不等于接收者附近的环境。隐藏站彼此听不到，却可同时干扰一个接收者；暴露站听到邻居，可能因过度退让错失本可并发的机会，但仍要检查接收端和 ACK 等反向链路是否安全。回看无线基础 P24–28。

碰撞避免是把风险拆开管理，不是承诺零碰撞

本课经典 DCF 路线是：物理及虚拟载波监听，满足 DIFS 与适用退避后发送；成功单播通常用 SIFS 后的 ACK 确认。SIFS 保护规定的响应，DIFS 给新争用留更长等待；PIFS 属于相应协调功能，不能当任意“高优先级用户”的特权。

NAV 根据收到的 Duration 等信息维护本地保留状态，不测量能量；争用窗口提供随机计数，忙时冻结，重新空闲满足条件后继续。RTS/CTS 把预约传到发送端及接收端邻域，缓解隐藏站，但本身有开销、也可能失败。CW 数值、时隙及帧间隔要与具体 PHY 或题设成套使用。回看无线基础 P29–48。

地址先分两对角色，再查 DS 方向

RA/TA 是当前无线一跳的接收者/发送者；DA/SA 是这次链路数据交付的目的/源。接收 AP 不一定是最终数据目的，所以无线帧才需要比单纯源、目的更丰富的地址安排。以下只整理本课传统数据帧，不套到所有控制帧或全部扩展格式。

To DS 为 、From DS 为 ：地址一为 DA（也是 RA），地址二为 SA（也是 TA），地址三为 BSSID。

To DS 为 、From DS 为 ：无线站发向分配系统，地址一为接收 AP 的 BSSID（RA），地址二为源站 SA（TA），地址三为 DA。

To DS 为 、From DS 为 ：从分配系统发往无线站，地址一为 DA（RA），地址二为发送 AP 的 BSSID（TA），地址三为 SA。

To DS 为 、From DS 为 ：传统无线分配场景需要四地址，依次为 RA、TA、DA、SA。由此可见，原清单的“三种地址”只概括常见三地址数据帧，不能推成所有 802.11 帧都恰有三个地址字段。回看无线基础 P49–53。

用两次空口传输检验自己是否理解

伴读自拟：同一基础设施 BSS 的 A 经 AP 把数据发给 B，常规路径先 A→AP，再 AP→B。第一跳眼前接收者是 AP，最终目的为 B；第二跳眼前发送者是 AP，数据源仍为 A。改变的是当前一跳角色，不是把原数据源改成 AP。

不将 To DS/From DS 的四种组合压缩成一张无条件三地址表。

ACK 缺失不唯一证明发生碰撞，也可能是数据或 ACK 受噪声等影响。
