循环队列：先看指针定义，再判断队满

原题

CQ[0:10]为一循环队列，初态front＝rear＝1，画出下列操作后队的头、尾指示器状态。（1）d,e,b,g,h入队；（2）d, e出队；（3）i,j,k,l,m入队；（4）b出队；（5）n,o,p,q,r入队

已按课程PPT核实

front指队头元素；rear指队尾下一位置。CQ[0:10]有11格，但采用留空一格法，最多存10个元素。

判空：front == rear；判满：(rear + 1) % 11 == front。

可直接提交的答案

操作后frontrear长度队头 → 队尾
（1）165d, e, b, g, h
（2）363b, g, h
（3）308b, g, h, i, j, k, l, m
（4）407g, h, i, j, k, l, m
（5）4310g, h, i, j, k, l, m, n, o, p

第（5）步只有n、o、p成功入队。此时front=4、rear=3，满足(3+1)%11=4，队满。q上溢，r也不能入队；若遇错即停止，则r未执行。无论哪种解释，最终有效状态不变。

完整11格指针图

绿色箭头是front，紫色箭头是rear。短横线表示不在当前有效队列中，不代表出队时必须清空内存。

一步一步推导

  1. （1）先存后移尾：d、e、b、g、h写入下标1到5，rear到6，front仍为1。
  2. （2）出队只移头：删除d、e后，front从1到3；rear仍为6。
  3. （3）从10绕回0：i到m依次写入6到10。rear变成(10+1)%11=0，front仍为3。
  4. （4）移走下标3的b：front到4、rear仍为0。长度为7，还能放10−7=3个。
  5. （5）到满就停：n、o、p写入0、1、2，rear到3。下标3必须留空；再写q就会把满队和空队混淆，随后还可能覆盖有效元素。
自检与常见错误
  • 长度公式：(rear-front+11)%11；五步长度为5、3、8、7、10。
  • rear不是最后一个实际元素的位置；最终p在下标2，rear在下标3。
  • 不能把第（5）步写成rear=(0+5)%11=5：失败的入队不能移动rear。
  • 不可把本课的front误当成队头前一位置，否则格内元素会整体错一格。

课程依据：《第三章栈和队列(2).pdf》PDF第5页右中、下排及第6页上排，已逐页核验。题干依据用户提供的原始作业内容。

第 2 题 · 栈的应用

表达式求值：跟踪 NS / OS 双栈

试画出表达式A－B*C/D＋E**F;执行过程中NS，OS栈的变化情况;并给出相应的后缀表达式结果。

依据：第三章课件第 3 页，3.2.2「表达式的计算」。NS、OS、# 约定已核对原 PDF，并非猜测。

后缀表达式

A B C * D / - E F ** +

先看懂两只栈

  • NS：存操作数和运算结果。例如计算 B*C 后，B、C 出栈，结果 T1 入栈。
  • OS：存运算符，初始为 [#]；# 是栈底及输入结束标记。
  • 优先级：** > (*, /) > (+, -) > #。** 是一个幂运算符。
  • 操作数直接进 NS；当前运算符优先级高于 OS 栈顶才入栈，否则先归约栈顶，再用同一个当前符号继续比较。# 与栈底 # 相遇时结束。
  • 每次归约先弹出右操作数，再弹出左操作数，计算后把结果压回 NS。

题面分号不参与运算。按课件算法，实际扫描序列写成 A-B*C/D+E**F#。变量未给数值，故用 T1～T5 表示中间结果。

中间结果：按实际归约顺序编号

  1. T1 = B * C
  2. T2 = T1 / D
  3. T3 = A - T2
  4. T4 = E ** F
  5. T5 = T3 + T4

最终 T5 = A - (B*C)/D + E**F。

完整逐步栈变化

读表方向：栈底 → 栈顶（左 → 右）。每行显示该步执行后的栈；∅ 表示空栈。一个符号可能触发多次动作，所以同一符号会出现多行。

为什么后缀表达式是这个顺序？

操作数顺序仍为 A、B、C、D、E、F；运算符按实际归约顺序写到对应操作数后面：

B C * → B C * D / → A B C * D / -；另一部分为 E F **，最后再加 +。

因此后缀式为 A B C * D / - E F ** +，不包含结束标记 #。

容易失分的地方

  • NS 是操作数与运算结果栈，不是后缀表达式输出区。
  • 扫描到 / 时必须先归约 B*C；不能让同级的 *、/ 同时继续压栈。
  • 扫描到 + 时必须连续归约 / 和 -，然后才能把 + 压栈。
  • 归约时先弹出右操作数，再弹出左操作数，按“左 操作符 右”计算，尤其不能把减法、除法反过来。
  • 当前运算符触发归约后仍是当前符号，必须继续比较，不能直接读取下一个符号。
  • 后缀式中的 ** 须作为一个完整运算符；空格用于防止与 * 混淆。
  • # 仅为算法结束标记，不属于后缀表达式本体。
展开可直接整理提交的答案

设 NS 为操作数及运算结果栈，OS 为运算符栈；初始 NS=∅，OS=[#]。令 T1=B*C，T2=T1/D，T3=A-T2，T4=E**F，T5=T3+T4。将表达式末尾补 #，按上表给出的 0～17 步绘制双栈状态，所有横排栈均从栈底写到栈顶。最后 NS=[T5]，OS=[#]，# 与 # 相遇结束。

相应后缀表达式：A B C * D / - E F ** +。

作业3 · 题3 · 数组寻址

第3题：为什么答案是1120？

原题

有一个二维数组A[1:m,1:n]，假设A[3,2]地址为1110，A[2,3]地址为1115，若每个单元占一个空间，问A[1,4]的地址是多少？

一、先认清下标和存储方式

A[1:m,1:n] 表示下标从1开始的m行、n列数组。第一个下标i是行号，第二个下标j是列号；m为行数，n为列数。本题每个元素占1个存储单元。

二维数组在内存中仍然要排成一条线，课程给出两种顺序存储方法：

  • 行优先：先放完第1行，再放第2行；同一行相邻元素地址相差1。
  • 列优先：先放完第1列，再放第2列；同一列相邻元素地址相差1。

设首地址为B=LOC(A[1,1])，则两种公式分别为：

  • 行优先：LOC(A[i,j])=B+(i−1)n+(j−1)。
  • 列优先：LOC(A[i,j])=B+(j−1)m+(i−1)。

课程依据已核实：《第四章数组(1).pdf》PDF第1页左下角“1.二维数组Amn的顺序存储结构”同时列出上述两种公式；该页并未指定所有二维数组题一律按行优先。本题没有明说存储顺序，应由地址条件判断，而不是凭语言习惯默认行优先。

二、先排除行优先

如果按行优先：

LOC(A[3,2])=B+2n+1=1110，

LOC(A[2,3])=B+n+2=1115。

第二式减第一式：

5=(B+n+2)−(B+2n+1)=1−n，故n=−4。

但n是正整数列数，而且题中A[2,3]存在已经要求n≥3。因此n=−4不合法，题设不可能采用课程所述的标准行优先连续存储。

三、用列优先求行数m

按列优先：

LOC(A[3,2])=B+m+2=1110，

LOC(A[2,3])=B+2m+1=1115。

第二式减第一式，B被消去：

1115−1110=(2m+1)−(m+2)=m−1。

所以m−1=5，得到 m=6。代入可得首地址 B=1110−6−2=1102。

这里解出的是“每列有6行”，不是“每行有6列”。列优先公式中的整列步长是m。

四、求A[1,4]的地址

直接代入列优先公式：

LOC(A[1,4])=1102+(4−1)×6+(1−1)=1102+18=1120。

也可以不求首地址：从A[2,3]到A[1,4]，列号增加1使地址增加6，行号减少1使地址减少1，净增加5。因此：

LOC(A[1,4])=1115+6−1=1120。

五、配图怎么看

图中只画前4列，不表示n恰好等于4。列优先时从同一列上方往下读，地址每次增加1；第1列放完才接第2列。

行号i 第1列j=1 第2列j=2 第3列j=3 第4列j=4
1 1102 1108 1114 1120（所求）
2 1103 1109 1115（已知） 1121
3 1104 1110（已知） 1116 1122
4 1105 1111 1117 1123
5 1106 1112 1118 1124
6 1107 1113 1119 1125

特别注意：A[3,2]、A[2,3]、A[1,4]不是三个相邻存储单元。每次下标变化都是“行号−1、列号+1”，因此在本题存储模型下地址均增加m−1=5。

六、维数和题设边界

  • 已知A[3,2]和A[2,3]存在，只能先得到m≥3、n≥3。
  • 地址条件再推出m=6；不能由本题算出n的具体数值。
  • 要使所求A[1,4]存在，必须有 n≥4。这是题目询问该元素时隐含的有效下标条件。
  • 结论依赖课程讨论的标准连续顺序存储模型。如果额外明确要求“行优先”，则原题的两个已知地址互相矛盾，不应强行报告一个合法的行优先数组。

最终答案：A[1,4]的地址是1120。
